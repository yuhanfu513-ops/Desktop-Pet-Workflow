# macOS 实现与本机联动

## 原生桌宠

常见实现为 AppKit 的无边框透明 `NSPanel`、浮动窗口和 `AVAudioPlayer`；桌宠为独立应用，使用各自的 bundle identifier、偏好和音频资源。使用 PNG 的 alpha 通道，按比例绘制并留字幕空间。区分点击与拖动，避免拖动时播放。字幕与正在播放的片段绑定，替换或停止播放时清理旧动画、字幕和计时器。

用户要求点击随机说一句时，随机池可在一轮内不重复并避免跨轮重复；菜单选句与随机池使用同一清单。用户要求暂停续播的长音频时，保留播放位置，另提供从头播放，循环与结束行为按用户要求实现。对菜单、尺寸、长字幕及透明区域做实际检查。

## 许家印「邦友跳舞」生态

这位用户本机已有桌宠以 `~/Library/Application Support/DesktopPetDance/state.json` 协调跳舞；位置和代码可能被移动，先搜索项目并检查当前 `Sources/SharedDance.swift`，不要仅凭路径或旧副本假设。优先复用**当前**协议和实现：发布者按播放进度、时长和单调时间发布状态，跟随者在播放期间读取同一相位，暂停或退出时恢复自己的动画；超时/发布者退出后必须自动停止。不要让跟随者重复播放主音乐。

已有项目用原子写入状态、短周期更新和超时保护；保留其已有字段和测试用隔离状态路径，避免升级一个应用后其余应用协议不兼容。普通说话动画与联动动画发生冲突时，以实际联动需求协调，结束后恢复原有交互。用户要某个新桌宠跟跳时，可只更新该桌宠；只有协议确实改变且用户授权时才更新其他应用。

## 多桌宠交互

- 两个独立桌宠应各自可拖动和点击。靠近判断用屏幕坐标、窗口/图片实际边界，并用适当滞回避免边界抖动；退出、单独运行和跨屏时安全恢复。
- 分角色播放只让当前发声者动画、字幕与音频同步；连续点击或对话切换时避免重叠播放。距离靠近是否自动播放、是否倾斜及每次点击行为由用户决定。
- 已有 `Bridge.swift` / 本地消息协议是项目专属约束：先读其 `AGENTS.md` 和实现，遵守同步副本或防循环规则；不要把说话接力协议与跳舞状态协议混为一谈。

## 桌宠管理中心

若用户希望纳入现有管理中心，检查其源码和已安装应用，而非另做固定路径副本。注册准确的 bundle identifier、应用位置、名称和头像，调整列表尺寸及自检；兼容已有勾选召唤、关闭选中、关闭全部、已运行/未安装状态。通过正常退出请求关闭，并报告未退出的应用，不强杀；测试时使用隔离的模拟应用，避免关掉用户正在使用的桌宠。

Finder 扩展能给 Finder 文件夹背景提供菜单，但不应假定它一定出现在桌面空白处：在目标系统上验证，失败时说明实际限制并按用户选择提供独立管理应用或其他入口。
